# Development Setup

## Prerequisites

- Rust toolchain
- Cargo
- Dioxus CLI

## Install Rust

https://www.rust-lang.org/tools/install

## Install Dioxus CLI

```bash
cargo install dioxus-cli
```

## Verify Installation

```bash
rustc --version
cargo --version
dx --version
```

## Validate Workspace

```bash
cargo metadata --no-deps --format-version 1
```

## Build and Check

```bash
cargo check --workspace
```

## Run Tests

```bash
cargo test --workspace
```

## Format

```bash
cargo fmt --all
```

## Run Web Application

```bash
dx serve --package conctr-web-dioxus
```

## Run Desktop Application

```bash
dx serve --package conctr-desktop-dioxus
```

## Run Mobile Application

```bash
dx serve --package conctr-mobile-dioxus
```

Refer to the Dioxus documentation for platform-specific build requirements.

## Zed: Tailwind suggestions and colors in Dioxus

Open the repository root in Zed so [.zed/settings.json](../../.zed/settings.json)
applies. It enables the Tailwind language server alongside rust-analyzer, maps
Rust to HTML for class detection, and recognizes Dioxus `class: "..."` strings
with `experimental.classRegex`. Color previews use `lsp_document_colors: "inlay"`
and the server's `colorDecorators` setting.

`experimental.configFile` points at the UI library's Tailwind 4 CSS entrypoint and
associates app/library Rust files with its theme. This also avoids detecting the
original design kit's older Tailwind configuration. Restart the language servers
from Zed's command palette after settings changes; use Ctrl+Space inside a class
string. See [Zed Tailwind support](https://zed.dev/docs/languages/tailwindcss).

Completions and color swatches describe available utilities; they do not compile
CSS. The UI crate owns the compiler, theme and shipped output. Its input scans
library sources, workspace apps and `conctr-app-dioxus`, so new literal classes in
these consumers enter the shared bundle without app-level Tailwind configuration.

For workspace development, install tools once inside the UI crate:

```sh
cd crates/conctr-ui-dioxus
npm ci
```

Cargo rebuilds refresh the bundle and track consumer-source changes. For utility
edits handled only by DX hot reload, use `npm run watch:css` in the UI crate, or
trigger a Rust rebuild. Consumers still mount `ConctrStyles`/`ThemeProvider` and
need no local CSS input, npm package or generated asset. Commit the refreshed UI
bundle when distributing source changes. Standalone consumers receive prebuilt
CSS; their unscanned custom utilities cannot be generated by editor suggestions.

For example, `bg-red-400` changes a div's background once compiled. `fill-emerald-300`
affects SVG fills; use `text-emerald-300` for text. Prefer semantic classes such as
`bg-primary` and `text-primary-foreground` for theme-aware product UI. See the
[theming guide](theming.md) for ownership and customization.
